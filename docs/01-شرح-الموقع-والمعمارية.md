# LIONX — شرح الموقع والمعمارية

## 1. تعريف الموقع

LIONX هو **مول رقمي عربي** يجمع خدمات الألعاب والاشتراكات والبطاقات الرقمية والتسويق والأدوات والحلول الخاصة بالشركات في تجربة واحدة. النسخة الحالية تعمل من قاعدة كود مشتركة مبنية على Expo وReact Native؛ لذلك يمكن استخدام نفس المكوّنات على تطبيق الموبايل ونسخة Web المتجاوبة.

الهوية البصرية المعتمدة هي **RTL Black & Gold**: اتجاه عربي من اليمين إلى اليسار، خلفيات داكنة، بطاقات سطحية، وحدود ولمسات ذهبية. الواجهة تعرض بوضوح الفرق بين ما هو متاح في النسخة الحالية وما يحتاج إعدادًا إنتاجيًا لاحقًا.

> النسخة الحالية هي MVP عملي للعرض والتجربة والدفع اليدوي. لا تعتبر نظامًا ماليًا إنتاجيًا إلى أن تُضاف المصادقة الخادمية والتخزين الآمن وRBAC ومزود دفع معتمد.

## 2. الطبقات الرئيسية

| الطبقة | مسؤوليتها | أمثلة من المشروع |
|---|---|---|
| العرض | الشاشات، RTL، الهوية، البطاقات، النماذج، التنقل | `app/`, `components/`, `global.css` |
| البيانات المشتركة | الكتالوج، القطاعات، الأسعار الظاهرة، حالات العرض | `shared/catalog.ts` |
| الحالة المحلية | السلة، المفضلة، الطلبات، المحفظة التجريبية، سجل الأحداث | `lib/lionx-store.tsx` |
| دورة الطلب | إضافة خدمة، مراجعة، دفع يدوي، إثبات، نجاح، تتبع | `app/cart.tsx`, `app/checkout.tsx`, `app/payment-methods.tsx`, `app/order-success.tsx`, `app/track-order.tsx` |
| المحتوى | صفحات التعريف والثقة والمدونة والأكاديمية والأدوات والعروض | `components/architecture-page.tsx`, صفحات `app/` |
| الإدارة التمهيدية | واجهات موردين وتسعير وتحليلات ومحتوى ومستخدمين وتذاكر وكوبونات | `app/admin/`, `app/admin-operations.tsx` |
| Web Hosting | تصدير Web، تنظيف المسارات، النشر التلقائي | `web-dist/`, `scripts/prepare-github-pages.py`, `.github/workflows/deploy-pages.yml` |

## 3. خريطة تجربة المستخدم

تبدأ الرحلة من الصفحة الرئيسية، حيث يرى المستخدم القطاعات والخدمات المختارة، ثم ينتقل إلى المتجر أو البحث أو أحد المسارات الخمسة: **PLAY وPAY وGROW وDIGITAL وVIP**. عند فتح تفاصيل الخدمة يمكنه إضافتها إلى السلة، مراجعة إجمالي الطلب، ثم اختيار الدفع اليدوي.

مسار الدفع اليدوي له فرعان. الفرع الأول هو **دفع قيمة الطلب**، وفيه يأتي المبلغ من إجمالي السلة. الفرع الثاني هو **شحن رصيد الحساب**، وفيه يحدد العميل المبلغ بنفسه ضمن الحدود المعروضة. في كلا الفرعين يختار العميل وسيلة التحويل، ينسخ رقم محفظة LIONX، يكتب رقم المحفظة التي حوّل منها، ويرفع صورة أو PDF للإيصال. بعدها تُسجل العملية للمراجعة اليدوية ولا يُضاف الرصيد تلقائيًا.

| نقطة الرحلة | المسار |
|---|---|
| اكتشاف الموقع | `/` و`/(tabs)/index` |
| المتجر والقطاعات | `/store`, `/categories`, `/play`, `/pay`, `/grow`, `/digital`, `/vip` |
| البحث والتفاصيل | `/search`, `/service/[id]`, `/sector/[id]` |
| السلة | `/cart`, `/wishlist` |
| الطلب | `/checkout` |
| الدفع اليدوي | `/payment-methods`, `/payment-proof` |
| بعد الإرسال | `/order-success`, `/track-order`, `/orders` |
| شحن الرصيد | `/wallet` ← `/payment-methods?operation=wallet_topup` |
| الشركات | `/corporate`, `/quote-builder` |
| الدعم والثقة | `/about`, `/faq`, `/contact`, `/support`, `/terms`, `/privacy` |

## 4. معمارية الصفحات

تحتوي المعمارية الحالية على مسارات أساسية حقيقية ومسارات placeholder مقصودة. المسار الحقيقي يتصل بالكتالوج أو بالحالة المحلية، مثل تفاصيل الخدمة والسلة والـcheckout. أما placeholder فيعرض هيكل الصفحة ونصًا تمهيديًا واضحًا دون الادعاء بوجود خدمة إنتاجية خلفه.

صفحات المحتوى العامة والإدارية وLionxPay تستخدم مكونات مشتركة حتى يبقى التصميم موحدًا ويقل تكرار الكود. المسارات الديناميكية مثل تفاصيل المقال والكورس والأداة والخدمة والقطاع تستخدم معرفًا في الرابط؛ ولأجل GitHub Pages تم توليد عينة `demo` ثابتة للمعاينة، بينما تحتاج بيانات الإنتاج إلى قائمة معرفات معتمدة.

## 5. الربط بين Web والموبايل

لا توجد نسخة Web ثانية منفصلة. يتم تصدير واجهة Expo نفسها إلى `web-dist`، وتُجهز مساراتها للعمل تحت مسار المستودع `lionx-mobile-Public`. ملف `app.config.ts` يحدد `baseUrl`، وسكربت التجهيز يعيد كتابة أصول CSS وJavaScript وينشئ `index.html` للمسارات الرئيسية والمتداخلة.

## 6. حدود المعمارية الحالية

لا تحتوي النسخة الحالية على نظام حسابات إنتاجي أو قاعدة بيانات مالية أو صلاحيات Admin فعلية. صفحات LionxPay وAdmin موجودة لتثبيت المعمارية وتجربة التنقل، لكنها لا تنفذ بطاقات أو سحبًا أو KYC أو دفعًا آليًا. كما أن الإيصالات في النسخة الحالية تُستخدم محليًا للمعاينة ولا تُرفع إلى Object Storage خادمي.
