# LIONX — ما المطلوب منك الآن؟

## النتيجة المختصرة

الموقع جاهز للمعاينة والاختبار، والكود مرفوع على GitHub، ورابط GitHub Pages يعمل. المطلوب منك الآن ليس تعديل الواجهة، بل اعتماد القرارات التشغيلية التي لا يمكن تخمينها بأمان: مزود الدفع، الحسابات، المورد، الأسعار، سياسة المراجعة، والنطاق التجاري.

## الخطوة الأولى: راجع الموقع بنفسك

افتح رابط المعاينة الدائم:

`https://lionxagancy-pixel.github.io/lionx-mobile-Public/`

ثم جرّب المتجر والقطاعات وتفاصيل الخدمة والسلة وصفحة الدفع اليدوي. استخدم صفحة الدفع فقط كاختبار واجهة؛ لا تحول أموالًا حقيقية من أجل الاختبار قبل اعتماد Backend وتخزين الإيصالات.

صفحة الدفع اليدوي المباشرة:

`https://lionxagancy-pixel.github.io/lionx-mobile-Public/payment-methods/`

## الخطوة الثانية: أرسل قرارات التشغيل

| القرار المطلوب | الإجابة التي نحتاجها |
|---|---|
| مزود الدفع | اسم المزود الذي وافقت عليه وبيئة Sandbox المتاحة |
| طرق الدفع | بطاقات، محافظ، InstaPay، أو ترك الدفع اليدوي فقط في البداية |
| الحسابات | هاتف، بريد، Google، أو نظام آخر |
| المورد | هل سيتم ربط Gamsgo؟ وما قائمة الخدمات المسموح بها؟ |
| التسعير | markup، رسوم الدفع، الضريبة، التقريب، والعملة |
| شحن الرصيد | الحد الأدنى والأقصى، وهل يحتاج موافقة موظف دائمًا؟ |
| السحب | هل سيُتاح؟ ومن يوافق عليه؟ وما الحدود؟ |
| Admin | أسماء الأدوار: مالك، مشرف، مراجعة دفع، دعم، محتوى |
| الإيصالات وKYC | مدة الاحتفاظ، من يراها، ومتى تُحذف |
| النطاق | الاستمرار على GitHub Pages أم ربط نطاق مخصص |

## الخطوة الثالثة: جهّز الحسابات خارج الكود

أنشئ حسابات العمل الرسمية لدى مزود الدفع والمورد وخدمة البريد أو الرسائل إن لزم، وأكمل التحقق التجاري المطلوب. لا ترسل API Keys في المحادثة ولا تضعها داخل ملفات `app/` أو JavaScript الخاص بالويب. عند بدء التنفيذ الخادمي تُحفظ الأسرار في متغيرات بيئة أو Secret Manager، ويُستخدم Sandbox أولًا.

## الخطوة الرابعة: اعتمد بيانات الكتالوج

أرسل ملف الخدمات الرسمي، بحيث يحتوي كل سجل على معرف ثابت، الاسم العربي والإنجليزي إن وجد، القطاع، تكلفة المورد، سعر البيع أو قاعدة التسعير، زمن التسليم، شروط التنفيذ، وحالة النشر. لا يكفي اعتماد أرقام الأقسام الظاهرة في المعاينة إذا كانت مجرد بيانات عرض.

## الخطوة الخامسة: اعتمد سياسة الدفع اليدوي

حدّد من يراجع الإيصالات، الزمن المتوقع للرد، أسباب الرفض، طريقة التواصل، ومتى يسمح بإضافة الرصيد. يجب أن تكون الموافقة مرتبطة بحساب موظف مخول، وأن يظل لكل عملية رقم وسجل قرار. لا تعتمد على لقطة الشاشة أو حالة المتصفح وحدهما كإثبات مالي.

## الخطوة السادسة: ترتيب الحزمة التقنية التالية

بعد استلام القرارات والبيانات، يكون التنفيذ الآمن بهذا الترتيب: Backend وقاعدة البيانات، ثم الحسابات والجلسات، ثم Storage الخاص بالإيصالات، ثم Admin RBAC وسجل التدقيق، ثم محرك التسعير، ثم تكامل المورد، ثم Sandbox للدفع وWebhooks، ثم اختبار الإنتاج التدريجي. لا نبدأ LionxPay أو السحب قبل اكتمال هذه الطبقات.

## ما لا يجب عليك فعله الآن

لا تفعّل الدفع الآلي من الواجهة فقط، ولا تضع أي مفتاح سري في GitHub، ولا تحول أموالًا حقيقية إلى أرقام الاختبار، ولا تعتبر رصيد المحفظة الحالي رصيدًا حقيقيًا، ولا تنشر صفحات Admin على أنها لوحة تشغيل قبل إضافة RBAC وتسجيل تدقيق.
